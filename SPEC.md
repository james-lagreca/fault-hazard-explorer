# Fault MFD → Hazard Explorer — Build Spec

An interactive, GitHub Pages–hosted explainer + tool showing how the choice of
magnitude-frequency distribution (GR / truncated GR / characteristic / Mmax)
changes seismic hazard from a single fault, for a fixed slip rate. Authored for
Claude Code implementation.

---

## 0. The one architectural decision (read first)

GitHub Pages is **static hosting**. `openquake.hazardlib` is Python with compiled
dependencies and **cannot run in the browser or on Pages**. We reconcile the
"OpenQuake-backed" requirement like this:

- **Runtime engine = TypeScript**, shipped to Pages. Instant, no server.
- **hazardlib = offline validation oracle.** A Python script generates *golden
  fixtures* (MFD rates, moment balance, hazard curves) that the TS engine is
  tested against in CI. The site's credibility is "every release is asserted
  equal to OpenQuake within tolerance," not "OpenQuake runs on load."
- **(Optional, post-v1)** a pluggable *remote* hazardlib API (e.g. self-hosted on
  the NAS via Tailscale) that an "authoritative compute" button can call and
  overlay. Enhancement only — not on the critical path, and never required for
  the public site to work.

Rejected alternatives: Pyodide/WASM hazardlib (compiled deps — h5py, geos, numba
— won't load reliably); precomputed JSON grid as the *only* engine (kills free
parameter exploration). Precompute may still appear as a caching layer later.

- **Plotly** for the two log-scaled charts (MFD cumulative; hazard curve).

## 4. Engine spec (the part that must be exactly right)

All MFDs share one fixed fault **moment rate** `Ṁ₀ = μ · A · ṡ`
(μ = 3×10¹⁰ Pa, A = L·W in m², ṡ in m/yr). Only the MFD *shape* changes; each is
moment-balanced so ∑ rateᵢ · M₀(mᵢ) = Ṁ₀, with M₀(m) = 10^(1.5m + 9.05) N·m.

`engine/mfd.ts` — incremental annual rates per magnitude bin:

- **Truncated GR** — exponential 10^(−b·m) on [Mmin, Mmax], balanced.
- **Unbounded GR** — same, run to a fixed high cap (e.g. 7.5) as the reference
  line; flagged "no fault cap" (physically inadmissible above the area magnitude).
- **Characteristic (YC1985)** — **must match OpenQuake's
  `YoungsCoppersmith1985MFD`**: boxcar over [Mchar−0.25, Mchar+0.25], exponential
  on [Mmin, Mchar−0.25], characteristic density anchored per Y&C (≈ exponential
  rate one unit below). Do **not** hand-tune constants from memory — implement,
  then tune until it equals the golden fixture from
  `YoungsCoppersmith1985MFD.from_total_moment_rate(...)` (see §5).
- **Mmax model** — single characteristic near Mmax (narrow box), all moment there.

`engine/scaling.ts` — WC1994 `M = 4.07 + 0.98·log₁₀(A_km²)` (hardcode, certain);
Leonard2014_SCR coefficients **taken from and validated against** OQ's class.
Used for the "lock Mmax to area scaling" mode and the segmentation marker
(imposed Mmax < area magnitude ⇒ "same moment, more frequent, not bigger").

`engine/hazard.ts` — λ(PGA>x) = ∑ᵢ rateᵢ · [1 − Φ((ln x − ln PGAₘₑ𝒹(mᵢ,R))/σ)];
plus log-log inversion to read PGA at 475-yr and 2475-yr return periods.

`engine/index.ts` — pure `compute(params): EngineResult`. No DOM, no I/O, fully
unit-testable. `EngineResult = { mags, cumByModel, pga, hazByModel, momentRate,
scalingMag, recurrenceByModel, pgaAtRP }`.

## 5. Validation — the "OpenQuake-backed" mechanism

`validation/generate_fixtures.py` runs hazardlib for a fixed set of canonical
parameter combos (include the 40 km / Mmax 6.79 and 80 km / Mmax 6.8 cases) and
writes JSON: per-model incremental rates, moment rate, scaling magnitudes, and —
for the matching-GMM combos — hazard curves.

`tests/engine.test.ts` loads each fixture, runs `compute()` with identical params,
asserts:

- MFD rates, moment balance, scaling mags: **relative error < 1e-3** (these must
  match OQ essentially exactly — same math).
- Hazard curve: matches **only when the TS GMM and the OQ gsim are identical**
  (Phase 3). Until then, validate the *integration* by feeding both sides the
  same closed-form GMM; treat the toy-vs-real-gsim gap as known and out of scope.

Acceptance: CI is red if the TS engine drifts from OpenQuake. That red/green badge
*is* the credibility claim — put it in the README and on the page footer.

> Subtlety to budget for: full end-to-end hazard parity requires one real gsim
> reimplemented in TS (Phase 3). Implementing a published SCR gsim (e.g. a
> Somerville-2009-class model) exactly is non-trivial but bounded; pick the
> simplest NSHA-family model that's fully specified in closed form.

## 7. Milestones

**Phase 0 — Scaffold & pipeline.** Astro app, empty island rendering "hello", CI
deploy green, site reachable at the chosen URL. *Done when: a trivial change ships
to Pages automatically.*

**Phase 1 — Engine + validation.** Port `engine/*` to TS. Stand up
`generate_fixtures.py` and Vitest golden tests for MFD/moment/scaling. *Done when:
`compute()` matches hazardlib MFD rates < 1e-3 on all fixtures.*

**Phase 2 — UI.** Port the prototype's controls, two Plotly panels, per-model
readout table, presets, "lock to scaling" + segmentation marker. Responsive,
keyboard-focusable, reduced-motion respected. *Done when: the live tool reproduces
the prototype on mobile and desktop.*

**Phase 3 — Full-chain parity.** Implement one real gsim in TS; extend fixtures to
hazard curves; assert end-to-end parity with OQ. *Done when: hazard curves match
OQ within tolerance for the matching gsim.*

**Phase 4 — Depth (optional).** Epistemic logic-tree fans (Mmax / b-value /
recurrence-behaviour branches → hazard *band*); NSHA neotectonic-domain presets;
optional remote-hazardlib API overlay; explainer copy polish.

## 8. Out of scope (v1)

Multi-fault / fault-system rupture; full PSHA disaggregation; site-response beyond a
single Vs30; map/spatial output. Note these as "not yet," not "won't."

## Appendix — formula reference

- Seismic moment: `M₀(m) = 10^(1.5·m + 9.05)` N·m
- Fault moment rate: `Ṁ₀ = μ · A · ṡ`, μ = 3×10¹⁰ Pa
- Moment balance: scale shape g(m) so `∑ k·g(mᵢ)·M₀(mᵢ)·Δm = Ṁ₀`
- WC1994 area: `M = 4.07 + 0.98·log₁₀(A_km²)`
- Hazard: `λ(>x) = ∑ᵢ rateᵢ · (1 − Φ((ln x − ln PGAₘₑ𝒹(mᵢ))/σ))`
- Reference prototype (JS math + UI) and `hazard_api.py` (hazardlib backend
  pattern) accompany this spec.
