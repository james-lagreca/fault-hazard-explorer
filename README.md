# Fault MFD → Hazard Explorer

Interactive explainer + tool showing how the choice of magnitude-frequency
distribution (GR / truncated GR / characteristic / Mmax) changes seismic hazard
from a single fault, **for a fixed slip rate**. Static, GitHub Pages-hosted, with
a TypeScript runtime engine asserted equal to OpenQuake `hazardlib` in CI.

![validate](https://img.shields.io/badge/engine-validated_vs_OpenQuake-2e7d32)

## Architecture

GitHub Pages is static hosting and `openquake.hazardlib` cannot run in the
browser. So:

- **Runtime engine = TypeScript** (`src/engine/`) — instant, no server.
- **hazardlib = offline validation oracle.** `validation/generate_fixtures.py`
  generates golden fixtures (MFD rates, moment balance, area scaling, and the
  Allen 2012 ground-motion model) that the TS engine is tested against in CI
  (`tests/engine.test.ts`). The credibility claim is "every release is asserted
  equal to OpenQuake," not "OpenQuake runs on load." The whole suite holds to 1e-9.

The engine reproduces, bit-for-bit against OpenQuake:
- the moment-balanced GR / truncated-GR / **YoungsCoppersmith1985** / Mmax MFDs;
- Wells & Coppersmith (1994) and **Leonard2014_SCR** area scaling;
- the **Allen (2012)** cratonic-SCR GMPE with the Seyhan & Stewart (2014) site
  terms (`Allen2012_SS14`), with a Vs30 control driving the site response.

## Develop

```bash
npm install
npm run dev        # http://localhost:4321/fault-hazard-explorer/
npm run test       # engine vs golden fixtures (Vitest)
npm run build      # static output → dist/
npm run fixtures   # regenerate fixtures (uses hazardlib if installed)
```

> **Fixture provenance.** The committed fixtures in `validation/fixtures/` were
> generated against **OpenQuake 3.16.1** (conda env `nsha_oq316`) — their `oracle`
> field records the version. The `CHAR` model is generated by hazardlib's actual
> `YoungsCoppersmith1985MFD.from_total_moment_rate`, and the TS engine reproduces
> it to floating-point precision (~1e-15). The generator also round-trips every
> model's rates through `EvenlyDiscretizedMFD` to assert the moment balance, and
> validates area scaling against `Leonard2014_SCR`. The whole suite is asserted to
> **1e-9** in `tests/engine.test.ts`; `validate.yml` re-runs it in CI.
>
> To regenerate locally: `conda activate nsha_oq316 && npm run fixtures`.

## Layout

```
src/engine/     pure compute() — moment, scaling, MFDs, GMMs, hazard integral
src/tool/       island: controls ↔ engine ↔ Plotly plots
src/components/ HazardTool.astro (the interactive figure)
src/pages/      index.astro (editorial page wrapping the tool)
validation/     generate_fixtures.py + fixtures/*.json (the oracle)
tests/          engine.test.ts (golden-fixture parity)
.github/        deploy.yml (Pages) + validate.yml (OpenQuake gate)
```

## Hosting

Live at **<https://james-lagreca.github.io/fault-hazard-explorer/>** — a GitHub
project page deployed by `.github/workflows/deploy.yml` on every push to `main`
(`base` in `astro.config.mjs`). To move to a subdomain, set `base: '/'` and
update `site`.
